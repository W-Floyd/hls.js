# Modular build follow-ups

- Remaining feature code in `core`: MediaSource transfer in buffer-controller (~1.3 KB min, backs the public `transferMedia`/`attachMedia(mediaSourceData)`), LL-HLS parts and delivery directives (~4 KB min, `latency`), `EXT-X-SKIP` delta playlists (~1 KB), alt-audio blocking in buffer-controller (~0.6 KB), interstitial branches in hls.ts and `primaryPrefetch`; feature-only exports of shared modules (`cml-utils`, `timescale-conversion`, `codecs`, `date-range`, `user-agent`).
- Worker: `transmuxer-worker.ts` always registers `mpegTs` since classes don't survive the JSON config; an ESM `core` client using `workerPath` gets the full `hls.worker.js`. A per-feature module worker would fix both.
- Types for `hls.js/core` and `hls.js/features/*`: api-extractor only rolls up `dist/hls.d.ts` from `src/hls.ts`; `scripts/build-auto-types.js` shows the approach that keeps one Hls class. `MuxConfig` and the mediaCapabilities helper types are forgotten exports in the main API report.
- `cdn/server.js` bundles have no transmux worker (IIFE included), so TS transmuxes on the main thread. HTTP clients see a change only after `max-age` (ETags revalidate); content-addressed URLs would allow `immutable`.
- `cdn/server.js` and `bundle-features.js` only assemble from one split build, so `USE_LOGS=0` bundles need a separately built `dist/core`; a `nolog` bundle code would need a second split build in the image.
- `src/auto.ts` detects features from the manifest, the first media playlist and config only; features revealed later (keys in later segments, undeclared in-band captions) need `features`. Its prefetched first media playlist goes unused when ABR starts on another level. From npm (`hls.js/auto`) it needs `cdn`, since it defaults to its own URL as the bundle server.
